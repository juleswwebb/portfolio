01 / THE CHALLENGE

Start with the system.

Integrating a robot is difficult when every sensor speaks through a different example sketch and every fault disappears between runs. The RoboCup workspace connects the embedded firmware to a desktop console, making sensor state, drive commands and recordings available in one workflow.

The work spans firmware integration and supporting software. It includes grouped JSON telemetry, sensor and wiring views, local arena mapping, a mission planner and offline analysis of recorded sessions.

02 / ENGINEERING DECISIONS

The thinking behind the build.

01

Use one protocol across transports

Newline-delimited JSON carries grouped sensor readings and commands over direct USB serial or a Bluetooth serial bridge. Firmware-provided signal definitions let the GUI discover friendly names and units.

02

Make missing data explicit

Unavailable sensor values are transmitted as null and shown as invalid. A successfully opened serial port is treated separately from a healthy telemetry stream, avoiding false confidence in a connection.

03

Map with appropriate sensor roles

Encoder displacement supplies translation and BNO055 orientation supplies heading. Range observations add local evidence. This is dead reckoning: drift and slip remain, and the map does not establish absolute arena localisation.

04

Keep planning and drive behavior inspectable

Desktop tools expose sensor placement, encoder calibration, obstacle clearance and A* route previews. Drive watchdogs and stop conditions are represented in the firmware and control workflow.

04 / OUTCOME & LEARNING

What the work revealed.

The workspace implements a debug console, firmware protocol, recording and analysis tools, range visualisation, mapping and planning features. Recordings use SQLite-backed sessions, with offline viewers and command-line analysis to examine runs after a test.

Development status: the robotics work is ongoing. Local maps accumulate odometry error, and implemented navigation features require physical calibration and hardware validation.

Observability is part of the robot.

A clear view of invalid data, calibration and system state makes integration decisions easier to justify. The tools around the robot are as valuable as the control logic inside it.
